Version 3.0.0 Current

September 2026

Bug Fixes

  • Fixed billing always adding the newest lot instead of the oldest (FIFO), and the returned-stock lot showing the wrong item count and ₹0 MRP/price. Two separate bugs, both around CUSTOMER-RETURN lots: (1) ProductSelector's "Add to Bill" read getLotsWithStock() back-to-front on the assumption it returns lots newest-first, when it actually returns oldest-first — so it silently picked the newest lot with room instead of the oldest, most noticeable once a product had a recent CUSTOMER-RETURN lot. (2) A farmer-first return (create_farmer_return_v1) is supposed to top up one shared CUSTOMER-RETURN lot per product/branch, but an 2026-08-17 migration rewrote the function from an older copy and lost that reuse, so every return on a product with a prior return created a duplicate lot — splitting its stock across rows and, since pricing was never set on insert, showing ₹0 MRP/Selling in the batch picker. Fixed: lot selection now walks a small, unit-tested pickLotWithCapacity() helper instead of a hand-rolled reversed loop; the RPC restores the shared-lot reuse and seeds pricing from the inventory row (existing null-priced lots backfilled). See Returns and Inventory Logic: the CUSTOMER-RETURN lot.
  • Fixed dealers occasionally getting two bills from one checkout, most visible on poorly-connected branches (e.g. Korkolu): create_bill_v2 committed the bill, but if the response was lost on a flaky connection, the client treated it as a failure and silently retried through the offline queue with a fresh client_ref — which the existing client_ref dedupe on create_bill_offline_sync couldn't catch, since it was a genuinely new value. The client was already sending an idempotency_key that survives that retry unchanged, but create_bill_v2 never read or stored it, so it did nothing. create_bill_v2 now checks (dealer_id, idempotency_key) before inserting and returns the existing bill instead, closing the gap for both the direct call and the offline-sync fallback. Follow-up fix: create_bill_offline_sync was still hardcoding already_synced: false whenever its own client_ref was new, even when the wrapped create_bill_v2 call had just deduped the bill via idempotency_key — so a bill saved this way could still trigger a duplicate send-bill-whatsapp notification to the farmer even though no duplicate row was created. It now propagates create_bill_v2's own dedupe result instead. See Glossary: idempotency_key and Offline Sync.
  • Fixed a farmer's Items tab (and its per-item bill drilldown) never reflecting returns — get_farmer_items_v1/get_farmer_item_bills_v1 summed bill_items directly with no idea bill_return_items/bill_return_allocations existed, so purchased quantity/value stayed stuck at pre-return numbers forever. Stock and every balance figure (bill balance, farmer total due, statement closing balance) were always correct — only this one summary was stale. Also fixed a related cache gap where creating, editing, or undoing a return never invalidated the Items tab's query keys. See Returns.
  • Fixed returns being effectively invisible on the Bill History list, the farmer's own Bills tab, the Bill Details page, a farmer's Ledger tab, and in the Balance Statement PDF, even though the underlying numbers were right. Bill History (/bills) and the farmer Bills tab (/farmers/:id) showed no indication whatsoever — no badge, no column, nothing in either the desktop table or the mobile card — that a bill had any return against it. On Bill Details, a return only ever showed in a card at the very bottom of the page with nothing above the fold hinting it existed, and the per-item "N sold − M returned" note only counted bill_return_allocations (farmer-first returns), silently missing returns recorded via bill_return_items (bill-first returns) on the same line. A farmer's Ledger tab listed return entries but they weren't clickable at all — no way to see what was actually returned without leaving the page (and the underlying getFarmerReturnDetail(), reused from the Returns page's own modal, only ever queried farmer_return_lines, so even opening a bill-first return there would have shown zero items). In the Balance Statement PDF, getFarmerStatement() fetched only the bill_returns header (no line items from either return table), and the PDF template only ever printed an amount for bill/payment rows — a return row printed - and N/A in both amount columns despite the running balance visibly dropping, with no product/quantity breakdown at all.

    Bill History and the farmer Bills tab now show an orange "Return" badge on any row with a return (checking both bill_returns.bill_id and bill_return_allocations.bill_id, so it catches both return flows). Bill Details shows a "Return Filed" badge next to the branch badge that jumps to the returns section on click, and counts both return tables per item. A farmer's Ledger tab return entries now open a read-only modal (items, amount, notes) on click, powered by a fixed getFarmerReturnDetail() that merges both return tables. The statement now lists each return's items and prints its amount (in amber) in the PAID(-) column instead of a blank placeholder. See Returns, Farmer Ledger, Bill History, and Bill Detail.
  • Fixed apply_settlement_discount_v1 writing to bill_audit_logs columns (action, old_value, new_value) that were never part of the table — every settlement discount attempt failed with column "action" of relation "bill_audit_logs" does not exist since the feature shipped (2026-07-25). Now inserts into the table's real columns (user_id, changes_jsonb), same shape edit_bill_v1 already used.
  • Fixed the Stock & Purchase list and Billing screen showing different prices for the same product. Both now read the price of the FIFO lot that's actually next up for sale (see Which Price Actually Gets Charged?), instead of the list reading a separate, easily-stale inventory.selling_price default.
  • Fixed the "Edit" price modal (EditInventoryModal) only ever updating inventory.selling_price and never the active stock lot — a dealer could edit and save a price with no error, yet Billing kept charging the old, untouched lot price. The modal now updates selling_price/mrp/medicine_discount_percentage on both in one save (deliberately excluding cost_price — see Which Price Actually Gets Charged?).
  • Fixed the same modal's MRP field drifting a little further from the true value on every edit (e.g. ₹2790.75 → ₹2790.09) — it was reverse-calculating MRP from Selling Price ÷ Discount% on every open instead of using the real stored MRP, compounded by InventoryDetailPage never actually passing the real MRP into the modal at all.
  • Fixed Daily Book pages (and subpages) not scrolling on laptop-height screens — the app shell was locking to a fixed viewport height meant only for the billing/estimate wizards.
  • Added the standard back button to four pages that were missing it (Dues, Estimates, Staff, Billing Templates), for consistency with every other page.

New Bill — Desktop UX

  • The desktop payment panel (ProductSelector, right column of /bills/new) is now a collapsible Payment Details card — starts closed, expands into Payment Method / Amount Received / Settlement Discount on the left and a read-only Bill Summary breakdown on the right.
  • The action button reads "Payment" while the card is closed (clicking only opens it) and becomes "Review & Sign" once it's open, however it was opened.
  • Product catalog grid is now responsive — 2 columns below 1300px wide, 3 columns at 1300px and up — instead of always forcing 3 cramped columns on moderate desktop widths.
  • Removed a stray replay-on-remount animation from the "In Cart" badge that could re-trigger on unrelated re-renders.
